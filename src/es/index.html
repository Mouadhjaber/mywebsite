Perfil de ingeniería / 01

El software debe diseñarse como un sistema, no como una colección de pantallas.

Mouadh Jaber es un ingeniero de software sénior que trabaja en la intersección del desarrollo empresarial, la arquitectura de software y la integración. Su trabajo abarca telecomunicaciones, banca, seguros, transporte, suministro farmacéutico y tecnología agrícola: entornos donde importan la fiabilidad, la trazabilidad y el cambio meditado.

El enfoque de ingeniería comienza por los límites: comprender el proceso de negocio, mapear los flujos de datos e integración, definir las responsabilidades correctas de los componentes y, después, construir un camino desde una base de código mantenible hasta un servicio desplegable. Eso significa trabajar de forma deliberada con la arquitectura, las API, los datos, la seguridad y la entrega operativa en conjunto.

Su experiencia práctica incluye desarrollo backend en C# y .NET; servicios REST y WCF; identidad y autenticación de dos factores; microservicios y mensajería; Docker y migración a la nube; y prácticas de entrega como TDD, BDD, DevOps y DevSecOps.

Capacidad de ingeniería / 02

Ingeniería clara para sistemas que deben funcionar.

01 / DISEÑO

Arquitectura con intención

Traduzca las limitaciones técnicas y operativas en límites claros de los componentes. La experiencia incluye arquitecturas en capas, monolíticas, compuestas, en tiempo real, distribuidas y de microservicios, respaldadas por UML, Merise, DDD y patrones de diseño establecidos.

02 / CONSTRUCCIÓN

Desarrollo de aplicaciones empresariales

Diseñe y entregue servicios y aplicaciones mantenibles utilizando C#, .NET, ASP.NET, Web API, WCF, Entity Framework, LINQ, SQL Server y Oracle. Aplique Repository, Unit of Work, inyección de dependencia, MVC y MVVM donde sirven al sistema.

03 / CONEXIÓN

Integración y flujo de información

Cree los contratos y las rutas de integración que permitan que los sistemas se comuniquen: REST APIs, sockets, tuberías, JSON, sistemas de mensajería, Kafka, Protocol Buffers, FIX Protocol y arquitecturas orientadas a servicios.

04 / EVOLUCIÓN

Entrega segura y preparación para la IA

Mueva sistemas de forma segura desde el desarrollo a la producción a través de Docker, Azure componentes, DevOps, DevSecOps, CI/CD, TDD, BDD, Scrum, SAFe y ITIL. Aplique la misma atención a la seguridad, la integración y la gobernanza al introducir capacidades de IA o LLM en los flujos de trabajo empresariales.

Principios de ingeniería / 04

El trabajo detrás del software fiable.

  1. 01

    Hacer observable la complejidad

    Modele el dominio, documente las interfaces y haga explícitos los flujos de datos antes de que la complejidad quede oculta en el código y los procesos manuales.

  2. 02

    Diseñar para el cambio

    Utilice límites claros, componentes comprobables y contratos estables para que los sistemas puedan evolucionar sin reescrituras innecesarias.

  3. 03

    Entregar con conciencia operativa

    El desarrollo no termina con una construcción exitosa. La implementación, la seguridad, el soporte de producción y las personas que operan el sistema son preocupaciones de ingeniería.
