工程简介 / 01

软件应作为系统来设计，而不是一组屏幕的集合。

穆阿德·贾比尔是一名高级软件工程师，工作于企业开发、软件架构与集成的交叉领域。他的工作涵盖电信、银行、保险、交通、药品供应和农业科技——这些环境都重视可靠性、可追溯性和审慎的变更。

工程方法从边界开始：理解业务流程，梳理数据与集成流，定义合适的组件职责，然后构建一条从可维护代码库到可部署服务的路径。这意味着要把架构、API、数据、安全和运维交付放在一起审慎推进。

他的实践经验包括 C# 与 .NET 后端开发；REST 与 WCF 服务；身份与双因素认证；微服务与消息传递；Docker 与云迁移；以及 TDD、BDD、DevOps 和 DevSecOps 等交付实践。

工程能力 / 02

为必须可靠运行的系统提供清晰的工程。

01 / 设计

有意图的架构

将技术和操作限制转化为清晰的组件边界。经验包括分层、整体、复合、实时、分布式和微服务架构，由 UML、Merise、DDD 和既定设计模式支持。

02 / 构建

企业应用开发

使用 C#、.NET、ASP.NET、Web API、WCF、Entity Framework、LINQ、SQL Server 和 Oracle 设计和交付可维护的服务和应用程序。在为系统服务的地方应用Repository、Unit of Work、依赖注入、MVC和MVVM。

03 / 连接

构建让系统通信的契约和集成路径：REST APIs、套接字、管道、JSON、消息传递系统、Kafka、Protocol Buffers、FIX Protocol和面向服务的架构。

04 / 演进

通过Docker、Azure组件、DevOps、DevSecOps、CI/CD、TDD、BDD、Scrum、SAFe和ITIL，将系统安全地从开发转移到生产。在将人工智能或LLM功能引入企业工作流程时，对安全性、集成和治理给予同样的关注。

工程原则 / 04

可靠软件背后的工作。

  1. 01

    让复杂性可观察

    在复杂性隐藏在代码和手动流程中之前，对域进行建模、记录接口并使数据流变得明确。

  2. 02

    为变化而设计

    使用清晰的边界、可测试的组件和稳定的合约，这样系统就可以不断发展，而无需进行不必要的重写。

  3. 03

    以运维意识交付

    开发并不以成功构建而结束。部署、安全、生产支持和操作系统人员都是工程问题。
